# アクションの同名保留を接触内容の照合へ変更

電話履歴の「【電話】1回目」を取引先名と同じように一意と扱っていたため、別施設への電話まで登録保留になっていた。Notionの候補照合、作成予約、Zoho候補照合をアクション専用の内容比較へ変更した。他DBの名称による照合は維持する。

- Notionと原本の予約：確定した取引先1件、アクション日、種別、履歴メモ、先方担当者、案件ID。タイトルは識別に使わない。
- 外部登録の予約は案件IDを除いた内容で一意にし、API反映待ち中の別案件二重登録も防ぐ。
- Zoho：取引先ID、日付、種別、履歴メモ、先方担当者。案件の対応欄がないため、案件だけが異なる同内容候補は保守的に保留する。
- 案件なしは正常。取引先不明・複数は保留する。同内容の別原本も自動で別物と断定しない。
- 原本・候補の照合欄が欠落、型違い、途中切れなら登録しない。正当な空欄とAPI応答の欠落を区別する。
- 日時付きの日付は、記載された暦日で照合・Zoho作成する。タイムゾーンを別地域へ変換しない。
- 分割照合のしおりには、方式バージョンと解決済み外部ID・比較値を含める。対応表変更時は全件を再照合する。
- 既存のreserved/created予約は解除しない。結果不明のPOSTは繰り返さない。DB一意制約と原本・送り先のロックを維持する。
