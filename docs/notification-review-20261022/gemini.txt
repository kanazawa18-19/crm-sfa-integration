レビュー判定サマリー

判定: 要修正・要確認（BLOCKERあり）

送信ロジックの骨格: 宛先・件名・本文および送信成功時のプロパティ記録ロジックは全リポジトリで正しく維持されており、会社アドレスへの代送フォールバックを行わない方針も各テストを含めて適切に実装されています。

主要な課題: OAuthスコープの過剰付与、実行コンテキスト（GAS実行者）とエイリアス送信仕様の不整合、および実GAS反映時のトリガー停止手順に重大な懸念があります。

BLOCKER（修正・事前検証が必須の事項）
1. OAuthスコープの過剰権限指定（[https://mail.google.com/](https://mail.google.com/)）

問題点: 各マニフェスト（appsscript.json）において、従来の script.send_mail から [https://mail.google.com/](https://mail.google.com/) に変更されています。このスコープは受信トレイの全メール閲覧・完全削除を含むフルアクセス権限です。

影響: メール送信を行う目的に対して過剰特権（Over-privileged）であり、Google Workspaceの組織セキュリティポリシーに抵触して承認がブロックされる可能性や、セキュリティ監査上の重大な脆弱性要因となります。

対応: メール送信のみを要求する最小権限スコープ [https://www.googleapis.com/auth/gmail.send](https://www.googleapis.com/auth/gmail.send) を指定してください。

2. 実行アカウントと from エイリアスの整合性

問題点: GmailApp.sendEmail(..., {from: 'daizuhakkou0619@gmail.com'}) は、「該当GASスクリプトを実行するGoogleアカウントのGmail設定で、事前に『送信元エイリアス（Send-as）』として登録・確認（検証）済みのアドレス」 である必要があります。

影響:

もし実GASが会社用Workspaceアカウントやサービス用アカウントで実行される場合、無料Gmailアドレス（@gmail.com）をエイリアス追加できないポリシーになっているケースが多く、実行時に Exception: Invalid from header が発生してメール送信が完全に失敗します。

スクリプト実行者（トリガー作成者 / Webhookの実行ユーザー）が平本氏本人であることを全GASプロジェクトで厳密に確認・担保しない限り、デプロイ後に即時障害となります。

3. スコープ変更に伴う既存トリガーの停止（認可失効）

問題点: マニフェストのスコープを変更した状態で実GASを更新すると、既存の時間主導型トリガーはすべて「要認可（Authorization required）」状態となり、バックグラウンドでの自動実行が即座に停止します。

対応: 反映作業時は「マニフェスト更新 → エディタから手動実行して新規権限（OAuth同意画面）を本人が承認 → トリガーが稼働状態にあることを確認」という一連の移行ステップを即時に連続して完了させる必要があります。

4. kstep のマニフェスト管理不整合

問題点: kstep の差分では docs/analytics/insights-scheduler.gs のコードが GmailApp に変更されている一方、リポジトリ内のマニフェスト差分が含まれていません。

影響: 実GAS側で手動承認する運用であっても、ソースコードとリポジトリ構成の整合性が崩れ、clasp等の同期ツール使用時に認可スコープの先祖返りやデプロイエラーを招きます。マニフェストの差分もリポジトリへ反映させてください。

WARN（運用リスク・注意を要する事項）
1. 例外の握りつぶしによるサイレントフェイル（障害未検知）

対象: AnalysisSources.js, RawSources.js

問題点: try { GmailApp.sendEmail(...); p.setProperty(...); } catch (_) {} となっており、例外が完全に破棄されています。

影響: 送信元エイリアスの設定不備、認可切れ、Gmail送信クォータ超過（個人アカウントは1日100通、Workspaceは1500〜2000通）などで送信失敗した際、会社代送を行わない方針と組み合わさることで、一切のエラーログを残さず通知がサイレントに消失します。少なくとも console.error(e) 等でエラー内容をスタックドライバに残す構成を推奨します。

2. CRM-SFA実GAS原本への差分適用ミス（リグレッション）

注意点: CRM環境には「未反映の他変更」が存在するため、リポジトリ全体の上書きプッシュは厳禁です。

対応:

実GASエディタ上で現在のコード正本のバックアップ（新バージョンの作成またはコード退避）を取得する。

通知関連の関数差分のみをピンポイントで原本コードへ手動反映する。

既存の業務ロジックやCRM連携部分に差分が波及していないことを確認する。

3. 停止中添付スクリプト（attachment-sync）の誤起動

注意点: attachment-sync も修正対象に含まれていますが、停止状態を維持する指示があります。

対応: 認可取得のための手動実行時にトリガー登録関数（newTrigger を含む処理）を誤ってキックしないこと、およびトリガー管理画面で新規トリガーが登録されていないことを作業完了後に必ず確認してください。
