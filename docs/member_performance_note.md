# メンバー別パフォーマンス評価「スピード」指標に関する申し送り

**本noteはスピード指標のみを扱う。** ボリューム（相対正規化の限界を含む）・クオリティの
設計判断は本noteには記載がなく、`src/analytics/member_performance.py`の
`compute_member_performance`／`member_win_rates`のdocstringを参照すること。

営業部行動ガイドライン「パフォーマンス ＝ スピード × ボリューム × クオリティ」を
`src/analytics/member_performance.py`で実装するにあたり、既存DBスキーマへの新規プロパティ
追加を行わない範囲で算出した（今回のスコープ外）。特に「スピード」指標について、
本来の定義と実装内容に差分があるため、以下に申し送りとして記録する。

## 実装した内容（簡易代替指標）

ガイドラインが求める「スピード」は本来、一次返信3時間以内目標のような**一次返信時間の
実測値**を指す。しかし案件管理DB・アクション管理DBには「初回応答日時」に相当するプロパティ
が存在しないため、本実装では代わりに**「次回アクション期限遵守率」**を採用した。

- 案件管理DBの「次回アクション日」が過去日付になっているにもかかわらず、それ以降に
  当該案件へのアクションが1件も記録されていない案件を「期限超過」とみなす。
- （1 - 期限超過率）を「遵守率」としてスピードスコアに用いる。

## 限界

- あくまで「期限を守れたか／守れなかったか」の二値判定であり、実際の対応スピード
  （問い合わせから何時間で一次返信したか等）は測れない。
- 「次回アクション日」は営業担当者が任意に設定する予定日であり、そもそも短めに
  設定すれば遵守率が上がってしまう等、指標としてのぶれが本来のスピード指標より大きい。
- ガイドラインが重視する「意思決定とアクションの速さ」そのものの計測にはならない。

## 本来の計測に必要なこと

ガイドライン通りの計測（一次返信時間の実測等）を行うには、以下が必要になる。

1. Notion側の案件管理DB、またはアクション管理DBへの新規プロパティ追加
   （例:「初回応答日時」「問い合わせ受信日時」）。
2. 上記日時を記録するデータ収集の仕組み（手入力の運用ルール化、または問い合わせ受信
   〜初回アクション記録までを自動連携する仕組み）。

これらは既存DBスキーマの変更を伴うため、今回の実装スコープには含めていない。
将来的にNotion側のプロパティ追加が可能になった際は、本メモを起点に
`src/analytics/member_performance.py`のスピード指標算出ロジックを差し替えること。
