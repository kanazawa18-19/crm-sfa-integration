# Notionの次回アクションをGoogleカレンダーへ登録する

2026-11-24の単一予定仕様。2026-11-25の複数TODO・予定への拡張は [複数アクション仕様](calendar_multi_action_sync.md) を参照。新機能は既定OFF。本番未反映、実カレンダー書込み未実施。

## 登録内容

- 「次回アクション」の非空文字列を優先し、空欄なら「AI推奨アクション」を使う。
- 「AI推奨アクション日」の日付に終日予定を作る。日時が入っていても既存APIに合わせ終日とする。文章から日時を推測しない。
- 予定名は案件名＋アクション（長い場合は100文字で省略）。説明欄にはアクション全文・採用欄・Notion案件リンクを保持する。
- 既存仕様と同じ先頭の担当メンバーのGoogle連携先を使う。未接続は保留。顧客を参加者として招待しない。
- 「次回アクション日」は日付元に使わない。AI推奨アクション日が空なら保留する。複数候補は日本時間の今日以降で最も近い日を選び、全て過去なら最後の日を選ぶ。Notionの日付範囲はstart/endの候補から選び、期間内の今日を補うことはしない。年省略や相対日付は推測しない。
- 内容・日付・案件名・担当の変更通知を起点に、取得済み案件の5項目から予定を更新する。AI推奨アクションはカレンダー専用に読み、他のCRMへの同期対象へ追加しない。

## プレビュー

保存したNotionページのAPI応答JSONに対し、次を実行する。外部通信・書込みはない。

```sh
.venv/bin/python -m src.calendar_sync.preview /private/path/page.json
```

登録候補の予定内容・担当者Notion ID、または保留理由を表示する。候補表示は担当者メール解決やGoogle接続成功を保証しない。顧客原本のJSONをGitやVaultへ保存しない。

## 予定を消す・担当者を変える場合

- 日付／内容の空欄化、Notionでのアーカイブ・ゴミ箱移動では既存予定を削除しない。
- 担当者を変えた場合、旧担当者の予定は残る。移管は自動化していない。
- Google側で削除済みの固定ID予定は自動復元しない。再開時は同一性・削除意図の確認が必要。
- 同時処理でも同じ案件は同じイベントIDで作る。旧方式で作った予定は既存の案件タグ検索で更新する。ただし異なる変更が並行した場合の更新順序保証は未実装。

Notion案件DBの5項目の型をAPIで確認（AI推奨／次回アクション=rich_text、日付=date、担当=people、案件名=title）。当初の旧日付による調査では、本人担当・内容あり393件を全ページ取得して集計。日付未入力249、過去144、今日以降0。今日以降の本人担当案件の別クエリも0件。原本更新・カレンダー登録なし。

本人の追加指示により日付元を新設の「AI推奨アクション日」に変更。同欄がdate型（ID PwCJ）であることを実読。変更後の本人担当・AI推奨アクション日入力済みは0件（全ページ取得完了）。作成直後の観測値であり、今後のAI入力を保証しない。
