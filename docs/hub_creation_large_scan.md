# Zoho新規登録の大規模重複照合

Zoho一覧を200件×10ページまでしか確認しないため、2,000件を超える登録先では新規登録が保留され続けていた。小規模の既存経路は維持し、上限超過・照合時間切れを保存済み位置から再開する。

## 処理

1. 登録元・入力内容の指紋と照合位置を `HubCreationScan` に保存する。
2. COQLでID順に最大2,000件ずつ取得し、既存の名前・メール比較を行う。比較前に位置を進めない。
3. 全件の確認後、開始時刻以降に更新されたレコードも確認する。差分期間は1秒重ねる。
4. 差分確認が5秒以内で完了した場合だけ、登録元を再読込し既存の作成予約から1回作成する。
5. 時間切れは10分ごとの `hub-creation-reconcile` で再開。入力が変われば初めからやり直す。

全体の通信予算は240秒、Zoho照合は60秒。OAuth更新・通信再試行・待機にも残り時間を伝える。差分照合が追いつかない場合は3巡で保留し、無期限に再開しない。権限・応答不正などの保留は、問題を解消した後に登録元を再通知して再開する。

候補を見送っても候補の現在値を確認する。外部作成の結果が不明な予約は定期処理から再送しない。外部利用者が最終確認直後に同名レコードを作る競合を、外部の一意制約で完全に防ぐ変更ではない。

## 実運用の前提

- マイグレーション `20260928130000_hub_creation_scan` が必要。
- Zohoの既存モジュール読取に加え `ZohoCRM.coql.READ` が必要。9月28日の実読取1件照会は401 `OAUTH_SCOPE_MISMATCH`。認証権限の追加前は大規模照合が保留される。
- Prismaの移行は `DATABASE_URL_UNPOOLED` を優先。共有接続先（pooler）・接続先上書きは拒否する。通常の `DATABASE_URL` に代替できるのはlocalhostだけ。dashboard本番の変数一覧に `DATABASE_URL_UNPOOLED` 登録済みを確認（秘密値は取得せず）。
- 9月28日の証跡のみコミットd31c093で管理画面の再配備が移行ロック取得の10秒タイムアウトにより失敗。事後の読取では該当ロック0件。強制解放はしていない。
