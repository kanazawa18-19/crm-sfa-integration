# 連携状態画面

管理者が共通設定の「連携状態」から、既存の診断機能を専用トークンの手入力なしで使う。接続確認と同期完了を区別する。

## 対象と範囲

- 画面は `/integrations`。管理者（master）だけが利用する。ページとAPIの両方で権限を確認する。
- ページを開いただけでは診断を開始しない。ボタンから手動で確認し、結果は対象ごとに表示する。
- Notion、kintone、Zoho、Google認証、スプレッドシート、シートの行作成設定、Slack、MAのページ応答、データベース、二重実行防止、更新通知の受信記録、シート作成待ちの12項目を扱う。
- 既存バックエンド `/api/diagnostics/integrations?only=対象` を用いる。レコードの作成・変更・削除、同期の再実行、Slackへの通知は行わない。既存診断では認証用アクセストークンの更新や診断専用ロックの取得・解放が起こる場合がある。
- DB構造の変更は不要。今回の画面追加は、未完了のシート整合性レビュー・本番修復とは別イシュー。

## 表示の意味

| 表示対象 | 確かめること | この画面では保証しないこと |
|---|---|---|
| 外部サービス | 接続・認証・必要な参照先の確認 | 全件の同期完了 |
| Slack | Botの認証 | 実通知の到達 |
| MA | ページのHTTP応答 | MA内部の同期処理の成功 |
| シート行作成 | 設定上の許可 | 実際に行が作られたこと |
| 更新通知の受信 | 受信記録の件数と日時 | 同期成功件数・古い記録だけによる障害判定 |
| シート作成待ち | 未処理・再試行打ち切り等の集計 | データ修復の完了 |

未設定・無効は異常と分ける。結果を取得できない場合は未確認として扱い、正常に見せない。時刻は確認した時点の記録であり、自動監視ではない。

## 情報の保護

- バックエンドトークンはサーバー内だけで参照する。
- 診断APIの生の `detail`、例外本文、自由形式の `extra` はブラウザへ渡さない。固定の日本語説明と許可した型・集計項目へ変換する。
- 診断先は固定の許可リストで制限する。全件を1リクエストにまとめず、対象単位で結果を回収する。
- 結果はキャッシュせず、認証失敗・通信失敗でも内部のエラー本文を返さない。
- 画面からの要求と接続先診断に別の時間制限を設ける。画面を離れたら後続の診断開始を止める。ただし、既にサーバーが受け付けた診断の停止は保証しない。

## 検証・配備

2026-09-09 主機CXの検証：

- 独立QA：33ファイル・289テスト、型検査、変更範囲の静的検査に成功。
- 独立セキュリティ・品質レビュー：画面離脱後の診断継続と滞留時の案内を修正し、再レビューで修正必須・修正推奨ともゼロ。
- 本番環境ファイルを含めない `/private/tmp` の隔離コピーで、画面→Next API→既存のバックエンド取得関数→合成HTTP応答→画面表示を確認した。認証ユーザーだけ合成値に差し替え、権限の拒否は単体テストで別検証。実DB・実外部サービスへの接続検証ではない。
- 初期表示は未確認12件。ページ表示だけでは診断しない。
- 最終版で認証切れを合成し、ブラウザで一括確認を操作。再ログインの固定案内と後続停止を確認し、バックエンドへの要求は0件。
- 合成応答で確認済み9件・要確認2件・未設定1件を表示。行作成許可・受信記録・作成待ちの件数を確認。
- 正常だった対象の再確認をHTTP 503にすると未確認へ更新し、合成の内部エラー文字列を表示しない。
- 5秒遅い合成応答中にサイドバーから別ページへ移動。受け付け済み1件だけが実行され、残り11件は開始されないことをサーバー側の件数で確認。
- 1440×1000、768×1024、390×844で表示確認。タブレット・スマートフォン幅で横はみ出しなし。
- 実ブラウザで同一送信元が403になる問題を発見し修正。Nextの内部URLではなくHostとOriginの照合を用いる。偽の転送Hostを信用しない回帰テストあり。
- Chrome拡張が付加したbody属性 `cz-shortcut-listen` による描画時の警告が出た。機能固有の不整合ではなく、警告を消すために本番コードを変更してはいない。

本番への配備・実サービスの診断は今回実施しない。
通常の `npm run build` は `prisma migrate deploy` を含むので、検証に使わない。

## 他社レビュー

同じ差分ファイルを、Gemini ProとClaude Opus 5（中）の新規チャットへ添付。認証情報・実顧客データを含まないコードと合成テストのみ。送信元ファイルは25,727文字、空白除外22,294文字、hash31 `491008934`、SHA-256 `ba214ced094986d7ff825e8b845477ac9c1480eb092151617f4e27a3e26e98c8`。ファイル添付のため、画面へ入力したコード本文のハッシュを読み戻した検証ではない。

- [Gemini Pro](https://gemini.google.com/app/8ba4a7f7e091d98c?hl=ja)：BLOCKER 0、WARN 2。非2xx応答の原因表示は、本文を直接表示せずHTTP状態に応じた固定文言にする方針で採用。古いブラウザの `AbortSignal.any` 互換対応は今回見送り。使用中Chromeで実操作を確認しており、旧Safari対応は本イシューの要件に含めていない。
- [Claude Opus 5・中](https://claude.ai/chat/4968a310-3e72-48ea-b0a9-c28f8efede00)：BLOCKER 3、WARN 9の指摘を受領し、一次コードと独立SECで採否を整理。
  - B1採用：Originを必須にし、送信元メタデータによる別サイト拒否も独立に行う。
  - B2はNodeとブラウザの仕様の混同。独立SECがNodeでHost/Origin設定・読み戻しを実測し、既存テストの空振りは否定。ただし期待値の断言を追加して根拠を明示。
  - B3は既存集計APIの契約との不一致。`outbox_stats()`はSQLの`GROUP BY status`で存在する状態のみ返すので、省略は0件を意味する。クエリ失敗は例外であり空集計として返らない。独立SECも不採用を支持。契約コメントと空集計の回帰を追加。`pending_oldest_age_days`は常に存在する別契約のため、欠落をnullとして受け入れる提案は不採用。
  - W4（401/403停止）・W5（不正応答から未確認への変換の回帰）・W8（テストのスパイ後始末）を採用。
  - W1の中止ボタン追加は見送り。現状は画面離脱で後続停止できる。W2の本番プロキシ構成は配備前確認に残す。信頼できない転送Hostを受け入れて回避しない。
  - W3の原因分類ログとW9のサーバー側頻度制限は未実装。管理者向け手動診断の範囲で、未確認を画面へ返す設計を維持。複数タブからの同時診断をサーバー側で抑止する機能はない。
  - W6は模擬テストの限界として妥当。別途、実ブラウザで画面離脱後のサーバー受信1件・後続11件未実行を確認し補完。W7は既存probeが日時をUTC補正してISO形式で返すため不採用。曖昧な日時を受け入れない。

外部レビュー後の限定修正は独立SEC・品質・QAで確認済み。最終修正必須・修正推奨ともゼロ。修正版そのものについて外部2社の再承認を得たという意味ではない。
