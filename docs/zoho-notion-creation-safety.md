# ZohoからNotionへの新規作成とID対応の復旧

2026-11-25。対象はZoho⇔Notion。kintone・業務スプレッドシート連携の整理は別件。

## 作成の順序

ZohoのDB種別＋原本ID → 永続予約 → Notionへ1回だけ作成要求 → Notion ID記録 → 対応表保存。

- 同じ原本の別通知でも同じ予約を使う。通信結果不明・取得ID保存失敗は予約を維持し、自動再作成しない。
- 同名・直近作成のページから作成結果を推測しない。
- 作成ID確定と対応表確認待ちは同じDBトランザクションで保存する。取得ID記録後に対応表保存が失敗した場合、作成済みページをアーカイブしない。次の通知では取得済みIDのページと元DBを確認し、対応表保存だけを再開する。
- 既存対応表へ追加する場合は読取時の同期時刻を条件とし、既存の他連携IDを保持する。保存応答が不明なら全ての指定済み外部IDを照合する。
- 対応表未確定は `mapping:notion` 保留として監視と通知に残す。対応表成立後に解除する。
- 作成途中のNotion通知による、逆方向のZoho新規作成も抑止する。

## 保留の扱い

`external:zoho:<db_key>:<external_id>` が登録元、`notion` が作成先。

| 状態 | 意味 | 次の処理 |
|---|---|---|
| reserved | 作成要求の成否またはIDの記録が不明 | 原本・作成結果を人が照合。予約を安易に解除しない |
| created | Notion IDを台帳へ保存済み | 対応表がなければそのIDで復旧 |
| mapping:notion / blocked | 対応表保存の確認待ち | 保存結果を再照合し、次の通知で復旧 |

ID不明の予約は同DBの未対応Notion新規登録も保留させる。確定IDが一致する取込ページと、DB単位の結果確認待ちは別の理由として表示する。既存IDに対応済みの通常更新とは区別する。

親取引先の対応IDがない場合、Zoho→Notionは未解決の関連欄だけを省く既存仕様がある。任意関連の案件では「ページ作成済み・関連付け保留」になり得る。親対応を確認してから履歴を回収する手動運用と、自動作成の仕様を混同しない。
