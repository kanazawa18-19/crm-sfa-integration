# 下書き誤登録を防ぐ送信証拠の確認

2026-10-19 の実物履歴で、4受付の元メッセージは DRAFT として追加・削除され、その後に別 Gmail ID の SENT メッセージ1通が作成されていた。個別ID・本文は私有証跡に保存した。名前や内容の重複判定を緩める修正は行わない。

Gmail の messagesAdded は送信限定ではない。既存移管計画に記載の `-in:drafts -in:chats` と取得後の判定が一致していなかったため、検索条件に依存せず取得実物の labelIds で最終判定する。

- Push・日次・GAS・メール照合受付・耐久保留再開で DRAFT を対象外にし、送信者一致だけでは送信と認めず SENT を要求する。受信メールの署名照合用途は維持する。
- ラベル欠損は SENT と推定しない。新規取得は再試行、既存受付は保留。旧耐久キューは metadata のみ取得し、確認不能なら本文・原文を残して再試行する。確定した対象外は done と監査理由を残し、本文・原文も残す。
- 保存済み受付の評価・処理・再照合・承認・再開をガードする。既存メール活動の通常 Notion 通知・共通新規作成復旧も受付の送信証拠で止める。
- 同一所有者・Gmail ID の再取得時は、本文が既存でも送信証拠を補完できる。完了状態・配送状態・活動IDは変更しない。証拠不足だけが理由で未作成だった保留のみ再照合待ちへ戻す。
- 公開行は生ラベルや本文を公開せず、サーバー計算の sent_evidence を含む。承認保存時は内部行の実ラベルを再検査する。

## 配備と実物訂正の境界

API先行配備後にGAS実体を更新する。現GASは dry-run 継続し、14日観測の起点・成功位置・トリガーをリセットしない。欠損ラベルを含む旧GAS要求は成功としない。DRAFT は excluded として正常に前進し、永久再試行にしない。

固定4件の誤活動の実物訂正は別の固定計画を作り、本文・日時・ID・親・受付・台帳・外部実物を読み戻してから行う。既存外部履歴を削除して隠さない。今回の製品修正だけでは、過去の誤活動・EmailLogの訂正は完了しない。固定7件と新規SENT1件は metadata の限定実読で証拠のみ補完し、固定7件を再配送しない。

Gmail公式根拠：
- https://developers.google.com/workspace/gmail/api/guides/drafts （送信時の下書き削除と新しいSENTメッセージ）
- https://developers.google.com/workspace/gmail/api/reference/rest/v1/users.history.list

手動の旧backfill CLIは今回実行しない。旧ラベル欠損の受付は、根拠なく手動承認して進めない。

## 追加レビューへの対応

実API取得時の labelIds 省略は空配列として扱う（SENTとは見なさない）。旧保存データ・旧GAS要求の欠損は不明のまま区別する。SENT の labelsAdded も履歴から取得し、同じIDが再出現した場合は最後のイベント順で処理する。通常通知の受付照会は正規UUIDと32桁表記を既存の action_id 一意索引で照会し、全件の文字列置換走査を避ける。

Slack・管理画面は証拠不足時に作成・訂正・再照合操作を隠し、管理者への元メール状態の再取得依頼を案内する。静的描画試験と型検査を実施し、本番PC/携帯での画面操作は未検証。正常8件の metadata 実読計画が揃っているため、配備前に証拠のみ補完する運用とし、既存状態・配送・活動IDを保持する。
