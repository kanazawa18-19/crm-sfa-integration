BLOCKER

B1 ラベルが空のメッセージを状態不明として扱っている
根拠：
・Gmail API の JSON 応答は、空の配列を省略します。ラベルを1つも持たないメッセージ（フィルタで受信トレイをスキップして既読にした受信メール、読んでからアーカイブした受信メールなど）は、labelIds キー自体が含まれません。
・get_message は data.get(“labelIds”) をそのまま使うため、これが None になり、eligible が MailStateUnknown を送出します。
・Push の履歴を処理する時点では、利用者がすでに既読・アーカイブしていることが珍しくないため、日常的に起こりえます。
影響（経路別）：
・Push の増分同期と日次同期：MailStateUnknown は404ではないため、_process_message_ref_or_skip を素通りして伝播します。historyId が進まず、そのメッセージの位置で担当者の取込全体が止まります（8月の404障害と同じ構造です）。EmailLog がすでにある場合も、safe_capture 経由で同じく失敗します。
・GAS：raw.labelIds || null によって null が送られ、旧GASの要求と区別できません。文書の方針どおり成功扱いにならないため、そのメッセージは永久に再試行され、dry-run の観測起点も前に進みません。
・旧耐久キュー：get_message_labels（fields=id,labelIds）も空の場合はキーが省略されるため、MailStateUnknown になり、その行は永久に failed になります。
修正案：
・「今回、実物を取得した応答」で labelIds が無い場合は、空集合として扱ってください。空集合なら、eligible は受信メールを対象とし、送信者が営業本人の場合は SENT がないため除外します。どちらの場合も SENT を推定することにはなりません。
・None（状態不明）として扱うのは、ラベルを保存していない旧データ（耐久キュー・受付の既存行）と、旧GASの要求だけに限定します。
・GAS は raw.labelIds || [] を送るようにし、キーが無い要求を旧GASと判定してください。
・回帰テストとして、labelIds キーの無い実応答形式で「受信メールは記録され、historyId が進む」ことと、「本人送信なら除外される」ことを追加してください。
・実物確認として、既読・アーカイブ済みの受信メール1件で応答に labelIds が含まれないことを確かめてください。

WARN

W1 停止中の Notion 編集が配送されずに消える
根拠：action_registration_blocked が True の場合、SkipTrackingDispatcher は skipped を返して処理を終えます。後で再配送するための記録は残しません。
影響：送信証拠が補完されるまでの間に、営業が該当するアクションページ（固定7件の正しい活動を含む）を編集しても、その内容は Zoho・kintone へ配送されません。証拠を補完した後も、次に編集されるまで差分が残ります。
修正案：
・API の配備前に、固定7件と新規SENT1件の証拠補完を済ませてください。
・停止した理由をページの同期メモに残し、補完後に再通知する手順を用意してください。

W2 後から SENT が付くメール
根拠：eligible は、本人が送信者のメールに対して SENT を必須としています。予約送信（SCHEDULED ラベル）や、送信の取り消し待ちのメッセージは、取得時点で SENT を持たない場合があります。そのメッセージIDのまま後から SENT が付くと、履歴上は labelsAdded として現れます。
影響：増分同期が messagesAdded だけを処理している場合、予約送信のメールは送信後も記録されません。日次同期の2日分の範囲から外れると、恒久的に取りこぼします。
修正案：予約送信を実物で1件確認し、SENT が同じIDへの labelsAdded で付く場合は、その SENT 付与も履歴処理の対象にしてください。

W3 アクション通知ごとの照会コスト
根拠：action_registration_blocked は、replace(data->>’action_id’, …) による全件走査を、SkipTrackingDispatcher と HubCreationService で1イベントにつき2回行います。
影響：EmailReview の増加に伴ってアクション同期が遅くなります。DB障害時には、メール由来でないアクションも含め、アクションの通知がすべて例外になります。
修正案：action_id を正規化した値の式インデックス（または列）を追加してください。照会の結果は1イベントの中で使い回します。

I2 不足しているテスト：

・GAS の旧要求（キーなし）と新要求（空配列）の区別
