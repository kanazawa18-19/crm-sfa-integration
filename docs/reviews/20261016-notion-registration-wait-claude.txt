WARN

W1. 登録待ちの付与は Dispatcher の1か所（prepared から作るメインレコードの項目結果）だけです。次の結果には registration_pending_tools が付かず、原因がID不足でも従来どおり500で再送され続けます。

_link_project(mapping) が返す結果

意図した範囲であれば、コメントかテストで「対象はメインレコードの直接項目のみ」と明示してください。関連レコードのID不足も同じ扱いにしたい場合は、そのレコードの mapping から判定する必要があります。

W2. dispatcher のテストは、Zoho のID欠落を FakeSyncTarget(always_skip=True) で模擬しています。そのため、本番の Zoho / kintone ターゲットが外部ID None を受けたときに「スキップを返す」ことは検証できていません。実際のアダプタが新規作成したり例外を送出したりする場合、今回の分類は前提ごと崩れます。仕様の「新規登録は行わない」に直結するので、実アダプタ（またはその薄いスタブ）に None を渡したときスキップ扱いになるテストを追加することを推奨します。

W3. has_partial_skips は登録待ちだけでも True のままです（テスト2で意図的に確認しています）。キュー経路以外で has_partial_skips から再送やHTTPステータスを決めている箇所がないか確認してください。特に src/api/routes/webhooks.py のルートが、handler_with_proxy を経由せず独自にステータスを判定している場合、そちらでは登録待ちが引き続き500になります。

W4. 運用上の見え方について。Notion からの再送が止まるため、ID補完後に誰かが再反映しない限り、その項目はずっと未完了のままです。現状、利用者が気づける手段は次の2つだけです。

Slack の registration_note。ただし unexpected が空でないときだけ付きます
WARNING ログ

ID不足によるスキップが _unexpected_skips で「既知のスキップ」に分類されると、Slack には通知されません。登録待ちの項目は unexpected の有無に関係なく通知する（または一覧できる）ようにするか、少なくとも ID不足のスキップが必ず unexpected になることをテストで固定してください。

INFO

I1. 判定は「ID欠落 かつ スキップ」という推定で、スキップの原因そのものは見ていません。IDが欠落していて、なおかつ認証情報未設定でスキップした場合も登録待ちに分類されます。どちらにしても再送では直らないので実害はありませんが、ログの原因ヒントがやや不正確になります。

I2. missing_ids は (KINTONE, ZOHO) をハードコードしています。外部IDを持つツールが増えたときの更新漏れを防ぐため、mapping 側に「欠落している外部IDのツール集合」を返すメソッドを置くことを検討してください。

I3. registration_pending_tools ⊆ skipped_tools という不変条件は、コメントで書かれているだけです。__post_init__ で検証すると、テスト2のように手で組み立てたときの誤りも検出できます。また、skipped_tools が set の場合は積集合も set になり、型注釈の frozenset と一致しません。frozenset(...) で包むと型が揃います。

I4. Slack 文面について。unexpected が {spreadsheet}、登録待ちが {zoho} のように食い違うと、「spreadsheet へ書き込めませんでした… 外部ID未登録: zoho」という1文になり、やや読み取りにくくなります。登録待ちは別の行か別の通知に分けると明確です。また、同じレコードが編集されるたびに通知が出るので、頻度によっては抑制を検討してください。

I5. テスト1で targets[Tool.ZOHO]._always_skip = False と非公開属性を直接変更しています。setter を用意するか、ターゲットを差し替える形にすると壊れにくくなります。

I6. テストで追加するとよいケース：

kintone と Zoho の両方でIDが欠落している場合
一部のツールは書き込み済みで、残りが登録待ちの場合
review_pending と組み合わせた場合
result に properties が無いときのフォールバック分岐（この分岐では登録待ちも再送対象になります）
SkipTrackingDispatcher の通知・ログに注記が付くこと
_partial_skip_summary の出力
