# Zoho自由記述の文字数上限

Notion原文を保持し、Zohoへ送信する値だけを実際の項目上限まで短縮する。
通常の新規作成と同期更新に共通の処理を適用する。本番反映前。

| 対象DB | 項目 |
|---|---|
| 法人 | 備考 |
| チェーン | メモ |
| 案件 | メモ |
| アクション | 履歴メモ |

- Zoho項目metadataの `data_type` が `text` / `textarea`、`length` が正の整数と確認できた場合だけ短縮する。上限内はそのまま送る。末尾に省略記号を追加せず、上限まで本文を残す。
- 名前、住所、電話、メール、URL、ID、選択値など、上記以外の項目は切らない。他サービスへの文字数対策は今回の対象外。
- 作成は既存のmetadata取得を再利用。更新は対象の自由記述が含まれるときだけ取得し、同じ配送処理内では接続先・モジュール単位で再利用する。次の配送では再取得する。取得失敗時は書き込まず、欠けた型・上限を推測して255文字にはしない。
- 案件のサイトコントローラー保存枠は全体を保持し、残りの文字数に本文を収める。枠だけで上限を超える場合は停止する。
- 既に上限まで埋まった案件メモで、本文を伴わず管理枠の長さだけ変わる更新は停止する。短縮済みのZoho本文から原文を復元できないため、Notionのメモ本文も同時に再送する。
- 省略は同期メモの専用区分「文字数上限による省略（原文はNotionに保持）」に項目名・元の文字数・送信文字数を記録する。本文や認証情報は転記しない。作成前に予定を保存し、成功後に送信済みへ更新する。作成確定と同じ更新で、本文を含まない省略記録を作成ジャーナルの既存reason欄へ保存する。成功後のメモ保存障害時は再開して記録を復旧し、記録済フラグにより後日の通常更新を巻き戻さない。旧形式など記録がない再開では「登録済み。省略結果の記録は未確認」と表示する。
- 更新の省略メモはDispatcherの同期処理内で収集する。低レベルのHTTPクライアントを直接呼ぶ保守スクリプト等は対象外。
- Zohoからの戻り通知と他ツールとの競合比較で、現在のNotion原文を実metadata上限で短縮した値と一致する場合は、Notionへの上書き候補にしない。比較候補から外しても配送先からは外さず、他ツールで本文が変わったら新しい短縮値をZohoへ届ける。現在の上限で再現できない短い前方一致は、過去の上限による省略と意図的な削除編集を区別できないため、その項目の逆同期を未完了として保留し、理由を記録する。意図した前方一致への短縮はNotionで行う。前方一致でない実編集がNotionに採用されたら古い省略・短縮保留メモを解除する。上限ちょうどの同一前方一致を人が意図して入力した場合も自動短縮との区別はできない。

比較用の読取では上記4項目だけZohoのAPI名から日本語キーを補い、案件メモは管理枠を除いた本文を用いる。生API値とModified_Timeは保持する。

作成記録の復旧とNotionメモの保存は別サービスのため同時確定できない。記録済フラグが保存される前に処理が途切れ、その間に本文が編集された場合、再開で古い作成時の省略記録を再保存する可能性がある。原文本体は変更しない。

公式仕様: [項目metadata](https://www.zoho.com/crm/developer/docs/api/v8/field-meta.html)、[作成API](https://www.zoho.com/crm/developer/docs/api/v8/insert-records.html)。

検証はローカルの模擬API・同期処理による。実サービスへの新実装の書込み試験は行わない。
