# 新規連絡先のNotionタイトル自動化

## 目的・対象

新規登録の連絡先だけを `名前（取引先名／メールアドレス／電話番号）` と表示する。
欠損は空欄とし、区切りは残す。電話は同じ連絡先レコードの携帯番号→直通TEL→会社TEL。
取引先マスターの電話は参照しない。複数の取引先名は「、」で連結する。

```text
新規ページ作成
  └─ Notion DB Automation（全ページ・Page addedのみ）
       1. 氏名（連携用） ← タイトル用氏名
       2. タイトル自動化 ← チェック
       3. 名前           ← 生成タイトル

その後の氏名・メール・電話・取引先関連の編集
  └─ Notion DB Automation（対象チェック済みビューのみ）
       名前 ← 生成タイトル

同期・照合コード
  ├─ 対象チェックあり → 氏名（連携用）を外部の「名前」に対応
  └─ 対象チェックなし → 従来の「名前」を使用
```

初期化は必ず「氏名→対象フラグ→タイトル」の順。タイトルを先に装飾すると、
途中の通知で装飾タイトルを純氏名と誤認し得る。
数式の再計算だけではタイトルは書き換わらないため、Automationのアクションで保存する。
外部の定期実行・GASはタイトル生成には使わない。

## 利用者の入力

新規作成後の氏名入力・訂正は **氏名（連携用）** に入力する。
空ページを先に作った場合も同じ。ページタイトルは表示専用で、自動生成される。
タイトルを直接訂正しても外部の氏名変更には使わない。
対象チェックは制御用で、通常の入力ビューでは非表示にする。
会社TELはNotion内の欄として扱う。外部の同名電話欄との対応は未確認であり追加しない。

## プロパティ

| 名前 | 型 | 用途 |
|---|---|---|
| 名前 | title（既存） | 表示タイトル |
| 氏名（連携用） | rich_text | 純氏名の保存・入力 |
| タイトル自動化 | checkbox | 新規対象の識別。既存はfalse |
| タイトル用氏名 | formula | 初期化前後の氏名参照 |
| 生成タイトル | formula | 完成タイトルの組み立て |
| 会社TEL | phone_number（本人が新設済み） | 携帯・直通が空の場合のみ表示 |

タイトル用氏名：

```notion
if(prop("タイトル自動化"), prop("氏名（連携用）"),
  if(empty(prop("氏名（連携用）")), prop("名前"), prop("氏名（連携用）")))
```

生成タイトル：

```notion
if(empty(prop("タイトル用氏名")), "",
  prop("タイトル用氏名") + "（" +
  prop("取引先マスター").map(format(current)).join("、") + "／" +
  prop("メールアドレス") + "／" +
  ifs(not empty(prop("携帯番号")), prop("携帯番号"),
      not empty(prop("直通TEL")), prop("直通TEL"), prop("会社TEL")) + "）")
```

更新用Automationは条件を **any / OR** にし、Page added、氏名（連携用）、
携帯番号、直通TEL、会社TEL、メールアドレス、取引先マスターの各Is editedを登録する。
一般的なAny property editedでは隔離DBで更新への追従を確認できず、個別指定では確認できた。
取引先DB側の会社名だけの変更は連絡先の編集イベントにならないため、即時追従は保証しない。

## 反映・停止

1. DBに必要な欄・数式を追加。既存ページの値は更新しない。
2. 同期コードを反映し、`NOTION_CONTACT_TITLES_SCHEMA_READY=1` にする。
3. 新規/更新Automationを設定し、対象ビューがチェック済みだけに絞られていることを確認。
4. 初期化と更新Automationを有効化。既存一括更新は行わない。
5. API新規作成時の同時保存は `NOTION_CONTACT_TITLES_ENABLED=1` で追加できる。
   この設定が未指定/0でもNotionの新規作成Automationが初期化する。

新規の適用を止める場合は初期化Automationを停止し、ENABLEDを0にする。
**SCHEMA_READYは1を維持**。既に対象となったページの検索・同期に必要。
既存対象の表示更新も止めたい場合は更新Automationを停止する。
**対象チェックを直接外して停止しない。** 純氏名も消去した後にチェックを外すと旧形式と
区別できない。旧形式に戻すには、処理停止中にタイトルを純氏名へ戻し、整合性を確認してから
対象フラグを外す別の復旧処理が必要。今回の対象には含めない。

## 検証と制約

2026-10-17の隔離DBで、架空データだけを使って実通信を確認した。
API作成、純氏名編集、携帯/直通/会社TELの優先順位と空欄、メール空欄、空ページへの後入力、
既存対象外ページの電話編集でタイトルが変わらないことを確認。
実製品HttpNotionClientのcreate/get/updateも隔離DBで実行。
Zoho・スプレッドシートへの架空データ送信は行っていない。
実行中の既存姓名補完は開始前に確定した既存ページのリストだけを処理するため、新規ページは対象外。
実行中プロセスの再起動・コード差し替えは行わない。

本番設定・反映状況は `docs/evidence/contact-title-20261017/status.md` に記録する。

2026-10-18 本番反映時：関連先の明示的なprop参照はAPIで型エラーとなったため、
`format(current)`でページ表示名を取り出す式へ変更。既存1件を読み取り、実際の取引先名との一致を確認。
