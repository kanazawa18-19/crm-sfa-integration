# Slack携帯CRMレビューの反映（2026-10-02）

独立レビュー3件と、Gemini Thinking・Claude Opusのブラウザレビューを照合した。Gemini/Claudeへ渡した資料は鍵・顧客情報を含まない差分抜粋で、SHA-256は `410bcbc11856d8b74c08c88f5da55d5d7e798aa11c708226ea39f92004938379`。回答原文は同じフォルダに保存した。

| 指摘 | 判定・対応 |
|---|---|
| 既存同期との排他鍵が違う・DB接続が不適切 | 修正。既存の `lock_key` と直接接続を使用し、使い捨てPostgreSQLで同じ鍵を他接続が取れないことを確認。接続終了時にセッションロックは解放される。 |
| 同名案件・同日同名アクションの取り違え | 取引先名を候補に表示し、アクションにはメモ要約とID末尾を表示。新規アクションの表題には操作IDを含める。 |
| モーダルの背景更新が現画面を上書きする | 背景での `views.update` をやめ、Slackの画面応答で同期的に次画面を返す。Notion候補取得には短いタイムアウトを設定。 |
| アクション再送で二重作成 | 入力画面で操作IDを発行し、確認・受付画面まで引き継ぐ。受付画面を閉じると入力履歴を消す。作成応答不明は再作成しない。 |
| `stale_event` や一部同期失敗を完了扱い | 初回の `stale_event` と部分スキップは `partial` とし、本人DMで未反映を示す。新しい同期時刻を捏造した再配送はしない。 |
| ロック待ち・通知の無限再試行 | ロック待ちは30秒遅延し最大12回、DMも最大12回。処理待ちの先頭詰まりを避けた。 |
| 長いメモ・日時の日付化による上書き | 500字超の既存メモは編集欄を出さず、日時の既存日付が同じなら変更対象から外す。日付の解除を許可。 |
| FastAPI BackgroundTasksのVercel上での実行保証 | 本番未検証。書き込みは先にDBへ受付記録し、5分ごとの回収口を追加。ホーム描画はイベント受領後の背景処理なので、反映後に実環境で確認が必要。 |
| 作成後の監査記録例外で重複する懸念 | `record_notion_write` は内部で例外を捕捉する既存契約を確認。非冪等作成の応答不明は `unknown` として人が照合する。 |
| 新規アクションに案件リレーションがなく同期できない懸念 | Notion作成に案件リレーションを含め、既存の `HubCreationService` がNotion生ページから対応表を作る構成を確認。各同期先への実到達は未検証。 |

独立SEC/品質/QAのBLOCKERは修正または根拠を照合済み。レビュー原文の指摘すべてを実物検証済みとみなさず、Vercel上の背景処理、Slack携帯の画面、実Notion・同期先への到達を残した。
