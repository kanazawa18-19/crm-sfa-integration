## 未連携レコード

Notion発・シート発の未知レコードの自動作成は有効化しない。古い未連携レコードが大量に存在し、必須項目や重複判定が確定しないため。毎週、未登録件数・最新のNotionページ・要確認シート行を本人DMへ知らせる。新規作成漏れとは断定しない。

`scripts/inventory_unmapped_hub_records.py` はNotion6DB、対応表、シート全使用行を読み取りだけで照合する。Notionの1万件制限は作成時刻のキーセットで越え、通信切断・5xxは再試行する。出力はgitignore済みmigration_output配下。顧客項目の内容を保存せず、識別子・日時・行番号だけを残す。

```sh
.venv/bin/python scripts/inventory_unmapped_hub_records.py --mapping-token-env NOTION_API_KEY
.venv/bin/python scripts/report_hub_inventory.py --directory <今回の出力先>
```

途中中断時だけ同じ出力先に `--resume` を指定できる。対応表と走査済みページを再利用するため、再開前の編集・削除を厳密には反映しない。同一時点スナップショットではない。週次は毎回新しい出力先で走査する。6DB全てが完了し、各結果が6時間以内でなければ正常報告しない。

主機launchd `jp.cnctor.crm-sfa.inventory` が月曜06:17に実行。GAS・Vercelの1回の制限時間に収まらないため主機を採用した。稼働中の毎時監視とは別プロセス・別ロック。初回確認だけ、同じセッションで読み取った全6DBの新鮮な結果を利用した。19:38 JST、実launchd起動から本人DM受理・last_success保存まで確認（0.8秒。全件走査そのものは直前の調査で実施）。次週のlaunchdによる全件再走査は未実行。

- `mapped_key_at_other_row` / `mapped_key_without_row_index`：同期キーで既存の対応表に結び付く。新規未登録から除外。
- `row_mapping_mismatch` / `duplicate_mapping`：行番号の対応を点検する対象。同期キーまで未登録という意味ではない。現行Dispatcherのシート書込はキー優先で再検索し行番号を更新する。
- 空の同期キー、重複キー、削除ページを指すキーは別分類。同期キー列自体が無い場合は中断。
- 月曜の週次DMが来なければ主機の稼働・ログ・通知認証を確認する。正常0件とみなさない。
- 公開GitHub Actions版は `.github/workflows/hub-inventory.yml` に準備したが、`HUB_INVENTORY_ENABLED` 未設定で停止中。新しいSecrets配布は自動承認審査で拒否され、登録していない。主機稼働を迂回登録と混同しない。クラウドへ認証を追加配布せず、既存のローカル設定で処理する。

## 優先3項目

本人の委任に基づき、実際に値が使われ、型対応を確認できた3項目だけを選んだ。利用者へのヒアリングで必要性を確定したという意味ではない。最新200件のサンプルによる優先順位であり、全過去データの必要度を断定しない。

|連携|項目|実測・対応|
|---|---|---|
|kintone→Notion|アクション履歴の先方担当者（toPerson）|SINGLE_LINE_TEXT→TEXT、200件中100件に値あり|
|Zoho→Notion|案件の次回アクション日（field31）|text→DATE、200件中8件に和文日付あり|
|Zoho→Notion|チェーンのその他（field）|text→TEXT、200件中6件に値あり|

日付は有効なISO・スラッシュ・和文の年月日だけを変換する。「来週」、存在しない日、日時等は既存値を残す。Zohoは変更差分なので、明示的な空は消去として反映する。kintoneは全レコード通知なので、先方担当者の空は保留し、未同期時代の空値でNotionの実値を消さない。**kintoneで担当者を空にしても同期先は消えない**。消去はNotionで行う。

Notionからの3項目の外向き更新は、対象DBで変更した項目IDが明示された通知だけを通す。全項目へのフォールバックで、未同期時代の空欄が外部値を消すことを防ぐ。項目IDが一致しない場合は保留される。Notion発新規の自動作成は今回有効化していない。

Zohoの非空14件は全て対応するNotion項目が空だった。計画SHA照合・対応表再確認・両側再読取・空欄限定の補完を行い、8日付＋6テキストの計14件を書込後の読み戻しまで確認した。非空の既存値は上書きしていない。kintone最新200件は対応表がなく、今回の14件補完には含めない。Notion APIに条件付き更新がなく、最終確認直後の同時編集は完全排除できない。

全80項目を一括で有効化する案は見送った。選択肢の対応・型の不一致・相手ページの名寄せは業務上の意味を確定してから進める。83件から3件を `known_sync_gaps.py` から削除し、現在80件（kintone43、Zoho37／リレーション28、その他52）。
